## 4. Расчёт бюджета (3 сценария)

### Сценарий A — минимальный (текущая нагрузка ~5 поисков/день)

- **SerpAPI** $50/мес (≈4550₽) — 5000 req/мес, текущий расход ~960 → **хватает с запасом**
- **OpenAI** ~$1/мес (≈90₽) — embeddings копейки, LLM-naming тоже
- **DaData** free — 10k/день, не исчерпан
- **Прокси для yandex** $30/мес (≈2700₽) — пул 5-10 IP
- **Итого: ~$81/мес (≈7400₽)** — покрывает парсинг + боли

### Сценарий B — с отзывами через google_maps_reviews

Если включить отзывы через SerpAPI (надёжно, но дорого):

- Каждый поиск ≈ 200 компаний × 1 req reviews = 200 req/поиск
- 5 поисков/день × 30 = 30 000 req/мес
- Нужно **150 000 кредитов SerpAPI = тариф $275/мес** (≈25 000₽)
- **Итого: ~$306/мес (≈28 000₽)** — дорого, но отзывы гарантированы

### Сценарий C — гибрид (рекомендуемый, после проверки 11.08.2026)

- **Yandex отзывы** через прокси $30/мес — основной источник текстов отзывов (Playwright)
- **2GIS Places API** 6700₽/мес (10к запросов) — каталог компаний (название/адрес/телефон/рейтинг). Отзывов НЕ даёт.

- **OpenAI** $1/мес — embeddings
- **Итого: ~$96/мес (≈8700₽)** — отзывы идут через Yandex (основной) + Google (резерв)

## 5. Что нужно сделать (чеклист)

### 🔴 Критично (без этого парсинг/боли не работают)

- [ ] **2GIS Places API** (для каталога компаний) — купить тариф на [dev.2gis.com](https://dev.2gis.com) → сервис **Places API** (10 000 запросов за 6 700₽). Текущий ключ невалиден (0% успех). Places отдаёт название/адрес/телефон/координаты/рейтинг/количество отзывов.
  - ⚠️ **Places API НЕ отдаёт тексты отзывов** — для болей тексты нужны, их даёт только Yandex (через Playwright) или Google (SerpAPI). См. секцию «Правда про отзывы 2GIS» ниже.
  - Войти → «Мои приложения» → создать приложение → выбрать **Places API** → скопировать ключ
  - Вставить в `/app/settings/maps-providers` → карточка 2GIS → поле API Key → «Сохранить» → «Проверить»

- [ ] **Прокси для Yandex** — купить пул HTTP-прокси (5-10 РФ-IP). Без этого yandex-парсинг ловит капчу через 20-30 запросов.
  - Задать `USE_PROXY=true` и `PROXY_LIST=http://user:pass@ip:port,...` в env контейнеров celery-worker и celery-worker-search
  - Рекомендуемые: proxy6.net, proxyipv4.com, ipmobile (≈300₽/IP/мес)

- [ ] **OPENAI_API_KEY** — проверить валидность. На проде 66.7% успех → либо ключ на rate-limit, либо endpoint нестабилен. После фикса retry в коде должно стать ~99%. Если останется низко — проверить баланс/лимиты на platform.openai.com.
  - Если OpenAI блокирует РФ-IP — использовать прокси-зеркало через `OPENAI_BASE_URL` (например openai-proxy или свой reverse-proxy за границей)

### 🟡 Желательно

- [ ] **Anthropic API** — для naming кластеров (claude-3.5-sonnet даёт лучшие лейблы болей, чем gpt-4o-mini). Завести `ai_assistants` запись с `provider_type=anthropic`, `model=claude-3-5-sonnet`, api_key в config. Без этого будут fallback-лейблы «Кластер N».

- [ ] **AI-ассистенты** — проверить через SQL: `SELECT id, name, model, provider_type FROM ai_assistants;`. Должно быть ≥2: один для sentiment (haiku/mini), один для naming (sonnet/gpt-4o). На проде сейчас 4 ассистента — проверить что у них валидные api_key.

### 🟢 Опционально

- [ ] **SerpAPI тариф** — сейчас $50/мес хватает. При росте нагрузки (если включить отзывы google_maps_reviews) — поднять до $250/мес.

- [ ] ~~**2GIS платный план для отзывов**~~ — НЕВАЖНО: проверено 11.08.2026, ни на каком тарифе 2GIS не отдаёт тексты отзывов. Places API даёт только рейтинг/количество. См. секцию «Правда про отзывы 2GIS» ниже.

```bash
# 1. Проверить статус провайдеров (покажет key_invalid если ключ сломан)
# Через UI: /app/settings/maps-providers → кнопка «Проверить» на каждой карточке

# 2. Запустить тестовый поиск
# Через UI: /app/leads → «кофе» / «Москва»
```

## 6.5. Правда про отзывы 2GIS — проверено 11.08.2026

Запрос пользователя: «2GIS официально не отдаёт тексты отзывов через API — как так?». Я проверил **реально** (curl с прода, разные ключи/заголовки/branch_id), и вот факты.

### Что я проверил

| Endpoint                                                | Тест                                                                                                            | Результат                                                                                              |
| ------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| `public-api.reviews.2gis.com/2.0/branches/{id}/reviews` | curl с точными заголовками из кода (Referer/Origin/User-Agent как у сайта 2gis.ru), разными branch_id и ключами | 🔴 **HTTP 403 Forbidden** всегда — `"error_code":"FORBIDDEN","message":"Permission denied"`            |
| `public-api.reviews.2gis.com/v2.0/...` (новый путь)     | curl                                                                                                            | 🔴 404 Not Found                                                                                       |
| Официальный **Places API** (docs.2gis.com)              | чтение документации                                                                                             | ❌ отдаёт только `general_rating` и `general_review_count`. **Текстов отзывов нет ни в одном тарифе.** |
| `/2.0/reviews/list` (бывший платный Catalog)            | monitor прода: 8 вызовов/неделю, 0% успех                                                                       | 🔴 endpoint убран из продажи, free-план отдаёт 404 «Method not found»                                  |

### Вывод

**2GIS больше НЕ отдаёт тексты отзывов никаким способом.** Раньше в коде был fallback на `public-api.reviews.2gis.com` (widget API), но он закрыт — теперь стабильно 403. Официальный Places API принципиально не включает тексты отзывов (это бизнес-решение 2GIS — отзывы монетизируются через сайт).

Код Colaba (`twogis.py:_fetch_reviews_public_api`) ещё содержит этот fallback — он корректно логирует 403 и тихо завершается, не вали таск. Но **функционально путь мёртв**. Отзывы с 2GIS получить нельзя.

### Что это значит для стратегии отзывов

| Источник                                        | Тексты отзывов? | Что нужно                                                             |
| ----------------------------------------------- | --------------- | --------------------------------------------------------------------- |
| **2GIS**                                        | ❌ НЕТ          | только каталог компаний (Places API, 6700₽/10к запросов)              |
| **Yandex Maps** (Playwright)                    | ✅ ДА           | прокси от банов (~300₽/IP/мес), код уже реализован в `yandex_maps.py` |
| **Google Maps** (SerpAPI `google_maps_reviews`) | ✅ ДА           | SerpAPI $50-250/мес, код уже реализован в `google_maps.py:221`        |

### Проверка Yandex/Google (тоже реальная, 11.08.2026)

| Тест                                                               | Результат                                                                                   |
| ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------- |
| `curl https://yandex.ru/maps/org/{id}/reviews/`                    | 200 OK, 451KB, **без капчи** — но отзывы грузятся AJAX после рендера, в HTML их нет         |
| `https://yandex.ru/maps/api/business/fetchReviews?businessId={id}` | 200 OK, но отдаёт только новый `csrfToken`, не отзывы — нужен Playwright чтобы выполнить JS |

**Вывод по Yandex:** путь рабочий, но требует Playwright + прокси. Код `yandex_maps.py` это делает правильно — нужен только рабочий `PROXY_LIST`.

## 8. Цена молчания (почему это не было видно раньше)

До фикса в коде главная проблема была **не в сломанных ключах, а в маскировке ошибок**:

- `MissingAPIKeyError` наследовал `RuntimeError`, и все `except RuntimeError` его глотали.
- Сломанный 2gis-ключ → поиск завершался `status='completed'`, `error_type='EmptyResult'`, текст «источник ничего не вернул».
- Юзер (и админ) видели «Ничего не нашлось» и думали, что ниша пустая или продукт сломан — хотя реальная причина «ключ 2gis невалиден» была спрятана в логах Celery.
- Health-чек показывал `twogis: ok` потому что проверял только наличие ключа в конфиге, а не его работоспособность.

Теперь: сломанный ключ → честная плашка с ссылкой на настройки, health показывает `key_invalid`, monitor показывает 0% успех. Диагностика занимает минуты, а не недели.
